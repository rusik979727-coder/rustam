# ghost-editor

Одна запись на входе, один файл на выходе.

**Твоя работа (творческая)** — только две вещи, и обе живут в `$P/edit.json`:
1. **Выбор дублей** — какие куски исходника войти в ролик и в каком порядке (`takes`).
2. **Ритм** — где кульминации (`beats`): зум, звуковой удар, мем-реакция.

**Работа скриптов (всегда одинаковая)** — монтаж, анимация приближения, субтитры,
уровни звуковых эффектов, копирование ресурсов, контроль качества. Их параметры
не настраиваются из `edit.json` намеренно: каждый ролик собирается по одним правилам.

Обозначения: `$S` = `~/.claude/skills/ghost-editor`, `$P` = каталог проекта ролика (любой).
`build.mjs` сам копирует нужные шрифты/SFX/мемы в `$P/assets`, поэтому проект
самодостаточен и `$P/preview.html` открывается сразу.

## Два железных правила

1. **На экране нет ничего, чего не сказал говорящий.** Субтитры строятся только из слов
   транскрипта, попавших в выбранные дубли. В `edit.json` нет и не может быть полей с
   произвольным текстом (`title`, `text`, `caption`… — ошибка валидации). QC сверяет
   каждое слово в субтитрах с транскриптом.
2. **Мем — это реакция.** Он появляется В ЦЕНТРЕ кульминации (`"at": "center"`) или
   СРАЗУ ПОСЛЕ неё (`"at": "after"`), никогда ДО. Числовое `at` раньше середины
   кульминации или позже её конца + 0.5 с — ошибка валидации. QC проверяет ещё раз.

## Порядок работы

```bash
S=~/.claude/skills/ghost-editor
P=/path/to/project          # внутри лежит исходник, например raw.mp4

# 1. транскрипт со словами и таймкодами -> $P/transcript.json
python3 $S/scripts/transcribe.py $P/raw.mp4 --lang ru
#    (нужен faster-whisper или openai-whisper; можно положить свой transcript.json)

# 2. каркас проекта
node $S/scripts/build.mjs init $P

# 3. читай запись фразами с таймкодами исходника; ⟲ помечает вероятные повторные дубли
node $S/scripts/build.mjs view $P

# 4. пиши $P/edit.json (дубли + ритм), проверяй
node $S/scripts/build.mjs check $P

# 5. сборка: ассеты -> субтитры -> рендер -> QC -> preview.html
node $S/scripts/build.mjs $P
```

Код выхода сборки: `0` — QC пройден, `1` — ошибка плана/рендера, `2` — QC провален.
Провал QC — не сдавать ролик: исправь `edit.json` и собери снова.

## edit.json

Все времена — в секундах **исходника** (те же, что показывает `view`).

```json
{
  "source": "raw.mp4",
  "transcript": "transcript.json",
  "output": "out/final.mp4",
  "format": { "w": 1080, "h": 1920, "fps": 30 },
  "captions": { "maxWords": 3, "maxChars": 18, "position": 0.7, "uppercase": false, "highlight": "#FFD400" },
  "takes": [
    { "in": 2.80, "out": 5.40, "note": "хук, второй дубль чище" },
    { "in": 6.20, "out": 8.00 },
    { "in": 8.80, "out": 10.60 }
  ],
  "beats": [
    { "climax": [9.30, 10.44], "zoom": 1.3, "sfx": "boom",
      "meme": { "file": "memes/wow.png", "at": "after", "dur": 1.2 }, "note": "панчлайн" }
  ]
}
```

- `takes` — дубли в порядке показа. Не должны пересекаться по исходнику. Резать по паузам
  между словами, а не по середине слова (валидатор предупреждает о разрезанных словах).
- `beats[].climax` — отрезок исходника, где звучит кульминация (панчлайн, ключевое слово);
  обязан целиком лежать внутри одного дубля.
- `zoom` — 1.0…1.6. Скрипт сам делает плавный наезд к началу кульминации, держит до её
  конца (и до конца мема) и отъезжает. Автоматически добавляется `whoosh`.
- `sfx` — `whoosh | pop | boom | ding | click | riser` или путь к своему файлу в `$P`.
  «Удар» звука ставится на начало кульминации (у `riser` — заканчивается на нём).
- `meme.file` — картинка/gif/видео в `$P` или в `$S/assets/memes`. При появлении мема
  автоматически звучит `pop`. `dur` по умолчанию 1.2 с, максимум 3 с.

## Как выбирать дубли и ритм

- Первые 1–2 секунды — самый сильный тезис (хук). Приветствия и «итак» — вырезать.
- Из повторных дублей (⟲ в `view`) обычно берётся последний: говорящий переговаривал,
  потому что предыдущий не устроил. Сравни по паузам и оговоркам.
- Убирай паузы > 0.3–0.4 с между фразами — оставляй ~0.1 с воздуха до/после слов.
- Кульминаций мало: одна на 10–15 секунд. Если всё «бьёт», не бьёт ничего.
  Ближе 1 с друг к другу — предупреждение.
- Мем — только там, где есть на что реагировать. `center` — реакция прямо на слове,
  `after` — пауза-реакция после панчлайна.

## Что делают скрипты (фиксировано)

| Шаг | Как |
|---|---|
| Монтаж | trim каждого дубля, микрофейды 12/15 мс на склейках (без щелчков), concat |
| Кадр | заполнение под формат (cover + центр-кроп) |
| Зум | smoothstep-кривая: наезд 0.14 с, отъезд 0.28 с, рендер с 2× оверсемплингом |
| Мемы | 80% ширины, верх кадра, альфа-фейд 80/120 мс |
| Субтитры | Inter ExtraBold, ≤3 слов/≤18 символов, разрыв на паузах и склейках, подсветка текущего слова, слова кульминации крупнее |
| Звук | уровни SFX из `scripts/lib/levels.mjs` (whoosh −19, pop −15, boom −11, ding −18, click −20, riser −21 dB), голос 0 dB, двухпроходный loudnorm −14 LUFS / −1.5 dBTP |
| Ресурсы | шрифты, используемые SFX и мемы → `$P/assets` |
| QC | формат, fps, длительность, громкость ±1.5 LU, true peak ≤ −1 dBTP, чёрные кадры, замершая картинка, «мёртвый эфир» ≥ 0.8 с, субтитры = сказанные слова, мемы после кульминации |

## Файлы проекта после сборки

```
$P/edit.json              план (твой)
$P/transcript.json        слова с таймкодами исходника
$P/assets/                скопированные шрифты, sfx, мемы
$P/build/captions.ass     субтитры
$P/build/timeline.json    итоговая раскладка в времени ролика (дубли, кульминации, sfx, слова)
$P/build/qc.json          результаты QC
$P/out/final.mp4          ролик
$P/preview.html           плеер + таймлайн + QC
```

Отчитываясь пользователю, перечисли выбранные дубли (что вырезано и почему),
кульминации с мемами и итог QC (включая WARN).
